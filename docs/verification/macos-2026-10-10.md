# FluxEnv macOS 验证（2026-10-10）

## 环境

- macOS 15.6.1，Apple Silicon arm64。
- 系统 `/bin/bash` 3.2.57、zsh 5.9、Vim 9.1、Python 3.9.6。
- 已安装 Apple Command Line Tools，本机尚未安装 Homebrew。
- 开发和验证直接在 `main`，未创建分支或 worktree。

## 结果

所有运行时 Bash 文件和新增测试脚本逐个通过 `/bin/bash -n`；交互测试辅助文件通过 Python 语法检查。`git diff --check` 通过。环境中没有 ShellCheck，未执行 ShellCheck。

`bash tests/macos/run.sh` 全部通过，覆盖：

- 完整模拟安装、生成配置在系统 zsh 和 Vim 中实际启动、已有配置保留。
- 重复安装不重复插入配置块、不再次安装已存在工具。
- 含空格的配置目录和 Homebrew 路径。
- 预览不写入配置、不调用下载 / sudo / 设备改名。
- 中文设备显示名、合法 Bonjour / 主机名、改名前记录。
- 第二个系统名字写入失败时恢复全部旧值，原来未设置的 HostName 仍为空。
- 伪终端中的交互改名、非法名称重新输入、最终确认，以及取消确认。
- 跳过改名优先于显式设备名。
- Intel 架构的模拟路径。
- 缺参数、非法参数 / 名字、root、缺失开发工具、Linux 平台拒绝。
- 符号链接和不完整托管块在安装前拒绝。
- 软件安装失败后停止配置。
- 官方 Homebrew 安装器的下载 / 非交互执行 / 安装后发现流程（下载和安装器均模拟）。
- 禁止自动安装且缺少 Homebrew、首次安装预览、安装器下载失败。

测试使用临时目录和模拟系统命令，不改变 `HOME`，不接触真实终端配置、系统用户、软件安装或设备名。启动测试只使用临时历史和补全文件。

## 验证边界

未执行真实 Homebrew 下载、软件包安装、`chsh` 或设备改名；这些操作需要在可修改的测试 Mac 上完成最终验证。Intel 只验证了模拟架构路径，未在 Intel 硬件上运行。测试中的 Starship 是模拟命令，真实 Starship 配置检查由安装流程中的 `starship module character` 执行。

实际安装依赖官方 Homebrew 网络服务。首次 Homebrew 安装、设备改名可能需要管理员密码；缺少 Apple 开发工具时需要先完成系统安装窗口，再重新执行脚本。Vim 在交互模式中默认不安装；非交互通过 `--with-vim` 或 `ENABLE_VIM=1` 启用。
