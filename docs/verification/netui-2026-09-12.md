# NetUI 容器 DNS 修复验证（2026-09-12）

## 环境与复现

cannlab：Ubuntu 20.04.5 aarch64 容器、Linux 5.10、NetUI 0.2.3、sing-box 1.13.18。容器实例已与 9 月 7 日不同；当前两个节点均未包含上次临时修复的 bootstrap DNS。

新 SSH 会话正常加载代理环境变量，本地 mixed 代理在 127.0.0.1:10808 接受连接。直连 GitHub 成功；通过 HTTP/SOCKS 代理失败，Git 报 `gnutls_handshake() failed`。核心日志显示节点域名的 A/AAAA 查询访问内网 DNS 时约 4 秒超时。

## 根因与修复

旧分享链接模板包含 `route.auto_detect_interface: true`。按 [sing-box 文档](https://sing-box.sagernet.org/configuration/route/#auto_detect_interface)，该选项将出站连接绑定到默认网卡，主要用于 TUN 场景的路由环路防护。NetUI 分享链接生成的是本地 mixed 入站，无需此绑定。

底层 UDP 查询对比使用同一节点域名、内网 DNS、A 记录，仅改变 `SO_BINDTODEVICE=eth0`：

```text
bind_eth0=False: 0.001s rcode=0 answers=1
bind_eth0=True:  3.003s TimeoutError
```

两个独立代理实例的对比仅移除网卡绑定，未修改服务器、认证、TLS 或 DNS：

| 配置 | 原配置 | 移除网卡绑定 |
| --- | --- | --- |
| Hysteria2 | 4.003 s 后连接重置 | HTTPS 200，Git ls-remote 成功 |
| VLESS WebSocket | 4.002 s 后连接重置 | HTTPS 200，Git ls-remote 成功 |

显式公共 DNS 也能绕过故障，但本次修复移除产生故障的网卡绑定，继续使用系统路由和 DNS。该模板设置在 v0.2.2 中也存在，并非 v0.2.3 新增。

## 实际联网与边界

修复后两个节点的 GitHub API 和 VS Code 更新接口均返回 HTTP 200。VLESS WebSocket 完成 577110 字节 GitHub 页面下载（3.227 s）及完整 FluxEnv 克隆（9.511 s）；克隆测试使用临时 HOME，没有全局 Git 代理配置。

Hysteria2 的小请求恢复，但连续页面下载中仍观察到已经收到 HTTP 200 和部分内容后发生 20–30 秒传输停顿，完整克隆也有一次超过 70 秒。这与此前无法完成节点 DNS 查询的故障不同，尚未定位该传输停顿的上游原因。服务器默认切换到完整下载验证通过的 VLESS WebSocket 节点，保留已修复的 Hysteria2 配置。WebSocket 节点首次切换时还出现一次上游 HTTP 525，随后三次独立 API 请求均成功；本版修复不等同于消除上游节点的偶发故障。

后续同一 WebSocket 节点、同一仓库、并行的完整克隆对比进一步定位传输差异：HTTP/1.1 在 7.972 s 完成；HTTP/2 在 TLS、引用查询、git-upload-pack 均收到 200 后停顿，45 s 超时。两者使用相同的 NetUI 和代理配置。服务器 Git 2.25.1、curl 7.68.0；仅针对 GitHub 设置 `http.https://github.com/.version=HTTP/1.1`，避免该链路上的 HTTP/2 传输问题。未据此修改 NetUI 的全局代理或所有站点的协议选择。
